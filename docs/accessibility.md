# Accessibility baseline

Accessibility is a first-class requirement. This is the **baseline** built into the prototype; it is not a formal assessment (see [production-readiness-gates.md](production-readiness-gates.md)).

**Commitment (decision 73):** WCAG 2.2 Level AA. The Stage 1 threshold, the critical workflows and what Zeporah may say are in [manual-accessibility-review-protocol.md](manual-accessibility-review-protocol.md#commitment-and-stage-1-threshold-decision-73). No conformance claim is made.

## What's in place

| Area                 | How                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Semantic HTML        | One `h1` per page; landmark regions (`main`, `nav` with labels, `aside`); tables with captions and `scope` on headers; lists for lists; `fieldset`/`legend` for grouped choices.                                                                                                                                                                                                                                                                                                          |
| Keyboard             | Everything is a native link, button or form control. A skip link (“Skip to main content”) is the first focusable element. Dialogs use the native modal `<dialog>`, which traps focus and closes with Esc.                                                                                                                                                                                                                                                                                 |
| Focus                | A 3px high-contrast focus ring on every focusable element (`:focus-visible`). After client-side navigation, focus moves to the main region so screen-reader users land on the new page.                                                                                                                                                                                                                                                                                                   |
| Labels               | Every input is labelled with a visible `<label>`; hints are linked with `aria-describedby`.                                                                                                                                                                                                                                                                                                                                                                                               |
| Status announcements | A polite live region (`role="status"`) announces the outcome of every action — saved, sent, held, denied. Completed actions also show the same words in a visible note at the bottom of the screen, which stays until it's dismissed, replaced or the person changes page; while it shows, focused elements are scrolled clear of it (WCAG 2.4.11). Refusals are shown with `role="alert"` next to the form — inside the dialog when the action came from one, and the dialog stays open. |
| Not color alone      | Every state badge carries words (“Held”, “Waiting for review”); the unread badge includes visually hidden text; protected and care-team-only content are labelled, not just tinted.                                                                                                                                                                                                                                                                                                       |
| Text size            | The person's text-size preference (Standard / Larger / Largest) scales the whole interface. Layouts reflow at 200% zoom.                                                                                                                                                                                                                                                                                                                                                                  |
| Motion               | The only animation is a short fade-in, disabled for anyone who prefers reduced motion.                                                                                                                                                                                                                                                                                                                                                                                                    |
| Responsive           | Family screens work from 375px wide with no sideways scrolling (checked by the phone end-to-end tests); staff tables scroll within their own container. Standard buttons and navigation items are at least 44px tall; small buttons are 36px (above the WCAG 2.2 AA 24px minimum).                                                                                                                                                                                                        |
| Times                | Every time shown is absolute and never changes after the page loads. Auditable events (consent, authority, packets, the audit timeline, bereavement, escalations) show the date, year, time and zone, for example “Oct 8, 2026, 4:25 PM ET”. See [architecture.md](architecture.md#times-and-time-zones).                                                                                                                                                                                 |
| Language             | Plain language, short sentences, no shame or urgency wording (“When you can”, never “overdue”). Notifications never contain sensitive details.                                                                                                                                                                                                                                                                                                                                            |

## How it's checked

- `e2e/accessibility.spec.ts` runs axe-core (WCAG 2.0/2.1/2.2 A and AA rules) on the start page, nine family pages (coordinator), eleven staff pages (reviewer), fifteen staff pages as operations (including every household tab and a filtered queue), sharing and support as the patient, and the vault and a protected item as a proxy, plus a keyboard path: skip link → persona → navigation → focus lands on the new page. No axe rules are disabled.
- The end-to-end suite runs against an isolated test server (port 3100) with its own database (`.data/e2e-pglite`) and Vite cache (`.data/e2e-vite-cache`); a global warm-up loads every route before any test, so no page is compiled in the middle of a scan. Every test fails on any browser console error or uncaught page error, which is how hydration mismatches are caught.
- The consent tests run axe on the household confirmation panel and the reviewer queue; the P1 tests add the “Consents for you” page, the staff consent view with a correction request open, hospice settings, and the coordination queue on a phone (where each item becomes a card with the same fields and no sideways scrolling).
- Queue priority — a workflow ordering aid, not clinical urgency — is shown as a word, a shape (▲ ● ○) and a stated reason — never color alone.
- `e2e/auth.spec.ts` runs axe on the email-and-password sign-in page (empty and with an error), the valid and unusable invitation pages, and Hospice settings with an issued invitation link. It also checks that sign-in works by keyboard alone (Tab to each field, Enter submits) and that errors reach the live region. These are automated checks only: the new sign-in and invitation screens have **not** had a manual screen-reader or keyboard review.
- `e2e/assignment.spec.ts` runs axe on the unassigned care guide's home and households pages, the households list with its care-guide column, the Care team panel after an assignment, and the end-assignment dialog. It assigns by keyboard (select, Tab, Enter), checks that Escape closes the dialog and returns focus to its trigger, and checks for no sideways scroll at tablet width. These are automated checks only: the assignment screens have **not** had a manual review ([protocol, slice B](manual-accessibility-review-protocol.md#slices-not-yet-reviewed)).
- `e2e/team.spec.ts`, `handoff.spec.ts`, `register.spec.ts`, `family-people.spec.ts` (desktop and phone), `bereavement-followup.spec.ts`, `audit.spec.ts`, `reports.spec.ts` and `status.spec.ts` run axe on their pages and on the dialogs they open, including the change-role dialog (also checked for Escape and focus return).
- `e2e-readonly/readonly.spec.ts` (`bun run test:e2e:readonly`) starts its own server with `ZEPORAH_READ_ONLY=1`. It checks:
  - the banner appears once, as a status;
  - axe passes with it shown;
  - sign-in and reading still work;
  - staff and family changes are refused with the calm message, and nothing is written;
  - no sideways scroll at 375 and 320 px.

  These are automated checks only. The change-role dialog and the banner still need the manual checks in the protocol (slices C and J).

- The flow tests also run axe on onboarding, the vault, messages, sharing and a held packet, and check that the phone layout never scrolls sideways.
- Automated checks catch perhaps a third of real barriers. Testing with screen-reader, magnifier, switch and voice users — and with older adults and people under stress — is part of the production gate.

## Known gaps

- Screens are English only. The language preference is stored, but professional translation of safety, consent and boundary content is a production requirement.
- No dark mode or forced-colors-specific styling yet (forced colors falls back to system colors and remains usable).
- The staff workspace is designed for desktop and tablet; on a phone it works but tables need sideways scrolling inside their containers.
