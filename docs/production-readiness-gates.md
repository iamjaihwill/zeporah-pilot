## Known prototype shortcuts that a production build must replace

- Local email-and-password accounts ([authentication-and-access.md](authentication-and-access.md)): no MFA, recovery, SSO, device management or external identity provider. The persona picker and the reset control exist only behind the development gate (`ZEPORAH_DEV_SIGN_IN=1`, never in production).
- Embedded single-process PGlite database; no connection pooling, replication or row-level security policies in the database (tenant isolation is enforced in the service layer and by composite foreign keys).
- Notifications are in-app; opt-in family email nudges follow cadence and quiet hours, but only to a development mail sink (decision 23). No email provider is connected (decision 18).
- Invitations are never delivered by email: the inviter is shown a one-time link to pass on. Acceptance creates or links an account and joins the invited boundary. Care-guide assignment, reassignment with hand-over, bulk task assignment, planned absence with time-limited cover and handoff acceptance, staff deactivation and reactivation all exist (decisions 38, 40, 58–62). There is no identity-provider deprovisioning. Operations and reviewers see every household in their organization by role, which a production minimum-necessary review must revisit.
- Packet release grants a named recipient read-only access in Zeporah's recipient portal, with acknowledgement and questions (decision 45); access ends at a set time. No content is ever delivered outside Zeporah.
- Data retention, export and deletion policies are not implemented.

## In-product support for these gates (prototype only)

These support the gates; they don't close them. See [operations-runbook.md](operations-runbook.md).

- **Environment checks.** The server refuses `NODE_ENV=production` without a named `ZEPORAH_ENVIRONMENT`, and the development gate never works in production.
- **Read-only mode** (`ZEPORAH_READ_ONLY=1`) for incidents, with a banner for everyone.
- **Error references:** one structured server log line per unexpected error, with no request data.
- **System status and audit review pages**, including hash-chain verification.
- **Documented local backup and restore.** It isn't automated or managed.
- **Integration contracts with no live integrations** ([integration-readiness.md](integration-readiness.md)): every adapter refuses calls, and a guard test checks for outbound connections.
